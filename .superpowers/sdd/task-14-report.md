## Outcome

Task 14 adds a strict human-authored behavior manifest, a deterministic Python-AST
location verifier, byte-reproducible JSON and Markdown handbook projections, reverse
source/rule navigation, source and commit staleness findings, repository-contained
path handling, and initial source-controlled handbook artifacts.

The handbook remains a derived index. Human declarations state behavior; source syntax
only verifies that a declared module, class, function, async function, or method exists

governance policy, and active rules retain authority.

re-exported by the handbook package. `create_verification_record()` converts the richer
non-durable `HandbookVerificationResult` to that exact storage contract. No migration,

## Design and safety decisions

### Strict manifest and projections

`BehaviorManifest`, `BehaviorEntry`, `SourceBinding`, locations, reverse links, build
results, findings, and verification results are strict, frozen Pydantic contracts with
unknown-field rejection. Duplicate behavior identities, set-like declarations, and
source path/symbol pairs fail validation. Behavior dependencies and related-behavior
references must name another entry in the same manifest.

Manifest hashing uses a canonical semantic ordering. Behavior order, governing-rule
order, and source-binding order cannot change generated bytes. JSON keys and arrays are
stably sorted; Markdown is emitted from the same normalized projection. The combined
generated-artifact hash binds separate JSON and Markdown SHA-256 values without a
self-reference.

### AST verification only

The builder reads exact repository-canonical Python source and calls `ast.parse`. It
never imports, dynamically loads, evaluates, or executes a declared module. The AST
inventory records only symbol kind, module, line range, file hash, and symbol hash.
Unrelated source symbols do not become behaviors, and no syntax updates any
human-authored contract field.

### Containment

Every source and test path is resolved beneath a trusted declared repository root.
Absolute paths, drive/UNC paths, parent traversal, a symlinked root, symlinked parents
or leaves, and Windows reparse points raise `PathContainmentError`. Missing,
non-regular, non-Python, undecodable, unparsable, stale, or symbol-missing sources
produce fixed non-content-bearing findings. Static namespace checks run before and
after file reads.

The threat boundary matches existing artifact storage: a separate local process able
to replace filesystem entries concurrently is outside this component's guarantees.

### Source snapshot

The initial manifest binds four implemented behaviors to the real source commit
`c5de7d14f530e172216f35d8a5453057aa257f61`:

- artifact containment;
- protected-evaluation separation;
- transactional admission coordination; and
- whole-workspace integrity verification.

Generated artifacts necessarily live in a later commit. Binding them to the commit that
contains themselves would be a cryptographic self-reference, so the manifest records
the exact real source snapshot and verifies that every current bound source remains
clean against it and retains the exact canonical hash.

## Residual boundary

The handbook verifies human declarations and source freshness; it cannot prove that a
declaration is behaviorally complete or scientifically true. Source hashes are
repository-canonical text hashes, so checkout-only CRLF/LF differences are deliberately
not stale changes. The manifest snapshot must be advanced through ordinary review when
bound source behavior changes. Task 15 campaign evaluation remains unimplemented.
