# Task 14 implementation report: verified behavior handbook

## Outcome

Task 14 provides a strict human-authored behavior manifest, deterministic Python-AST
location verification, byte-reproducible JSON and Markdown projections, reverse
source/rule navigation, repository-contained paths, and source-controlled handbook
artifacts.

The handbook remains a derived index. Human declarations state behavioral truth;
Python syntax only verifies locations. Source, tests, governance policy, and active
rules remain authoritative.

Task 13's canonical append-only `HandbookVerificationRecord` remains unchanged and is
re-exported by the handbook package. `create_verification_record()` accepts only
results whose commit/blob provenance was verified. No Task 15, campaign, evaluator,
CLI, dependency, migration, or quality-registry scope was added by this fix.

## Canonical review fixes

### Git-backed provenance

- A declared object ID is resolved with Git and must exist as a commit. Missing IDs,
  blob IDs, and tree IDs have distinct stable findings.
- Every bound path is resolved as an exact regular blob in that commit. Its declared
  SHA-256 is compared with the exact committed blob bytes, not checkout bytes or a
  caller-supplied string.
- AST locations, file hashes, symbol hashes, `source_hashes`, and the actual source-tree
  hash derive from those committed bytes.
- `git diff --quiet --no-ext-diff <commit> -- :(literal)<path>` independently requires
  each checkout path to remain equivalent to the committed blob. Git clean filters and
  line-ending policy therefore decide checkout equivalence without normalizing a byte
  mismatch inside the handbook.
- Historical commits remain valid only while every bound checkout path matches them.
  A stale checkout is a failed verification with verified commit provenance; a missing
  commit, non-commit object, or mismatched committed blob is unverified provenance and
  cannot become a durable record.
- Git is invoked with an argument tuple, `shell=False`, validated object IDs, literal
  pathspecs, and a `--` boundary. Repository data cannot inject a shell command or Git
  option.

### Portable paths

All source and test paths must use one canonical forward-slash, repository-relative
syntax before any host `Path` resolution. Empty/dot/parent segments, redundant or
trailing separators, leading slash, drive/UNC/device forms, backslashes, colons,
Windows-forbidden filename characters, Windows reserved device names (including
case-insensitive `COM¹`-`COM³` and `LPT¹`-`LPT³` aliases with extensions), and
Windows-trimmed segments fail closed. Unrelated valid Unicode names remain accepted.
Existing symlink, junction, reparse-point, and resolved-containment checks remain in
force.

### Portable generated bytes

`.gitattributes` pins `docs/handbook/*.json`, `docs/handbook/*.md`, and
`docs/behavior-handbook.md` to LF. A fresh local clone created with
`core.autocrlf=true` rebuilds and byte-compares the manifest schema and both generated
artifacts without normalizing a mismatch away.

### Markdown structure

Every handbook-local text field is strict, non-empty, untrimmed, single-line, and free
of control, format, line-separator, and paragraph-separator characters. Plain Markdown
text uses punctuation escaping; code-like contexts use a delimiter longer than every
embedded backtick run. Adversarial headings, pipes, backticks, brackets, links, control
characters, and Unicode separators cannot introduce a fifth disclosure heading or
alter the approved four-level structure.

## Contract alignment

- Repository commits retain Task 13's `GitObjectId` contract: lowercase 40- or
  64-character object IDs.
- The generated handbook retains exactly four disclosure levels: summary;
  contracts/dependencies/rules; modules/symbols; and exact
  commit/path/line/hash/test context.
- Manifest models and result models remain strict, frozen, and closed to unknown
  fields. Duplicate set-like values, duplicate binding identities, inconsistent hashes
  for one bound path, incoherent commits, and unknown behavior references fail model
  validation.
- The source inventory still uses `ast.parse` only. It never imports, dynamically
  loads, evaluates, or executes declared source.

## Residual boundary

The handbook verifies declarations, exact committed source provenance, checkout
equivalence, and deterministic projection bytes. It cannot prove that a declaration is
behaviorally complete or scientifically true. The manifest snapshot must advance
through ordinary review when a bound source behavior changes. Task 15 campaign
evaluation remains outside Task 14.
